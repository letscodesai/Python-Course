03

Comparing Text

Strings can be compared too — but the rules differ from numbers in a few important ways.

Case-sensitive equality
>>> "cat" == "cat"
True
>>> "cat" == "Cat"
False
Different types, never equal
>>> 123 == "123"
False
>>> 12 == 12.0
True

Rule: numbers compare equal across int and float because they're both numbers underneath — 12 and 12.0 are the same value. A string is never the same value as a number, no matter what digits it contains.

Ordering strings: lexicographic comparison

< and > work on strings too. Python compares them character by character, left to right, using each character's underlying code — the same way a dictionary orders words, which is why this is called lexicographic order.

"apple" < "banana"

"a" comes before "b" in character order, so the comparison stops right there and decides the whole string.

"Zebra" < "apple"

This one surprises most people — capital letters sit before lowercase letters in character order, so every capitalized word sorts before every lowercase word, regardless of the letters that follow.

Two Common Mistakes

These trip up almost everyone the first time.

Rule: a single = always stores a value in a variable — it never asks a question. Here the second line doesn't compare score to 100, it silently overwrites it, so the original 90 is gone. Python won't catch this for you: = and == are both valid, just very different operators. Fix it by comparing with == instead: score = 90 then print(score == 100) — which leaves score untouched and correctly prints False.

Spacing matters too: <= is one operator, written with no space. < =, with a space between the two characters, is not the same thing — Python sees two unexpected symbols and raises a SyntaxError.

Predict the output
print(5 < = 5)
Output
SyntaxError: invalid syntax

There's no operator spelled < space = — Python needs them written together, with nothing in between.

One more: Python won't order-compare values that don't share a meaningful scale. < and > work between two numbers, or between two strings — but mixing a string with a number raises a TypeError, because there's no sensible answer to "is the word 'abc' less than the number 5?"

Without parentheses, Python still has to pick an order. Arithmetic happens before comparisons, and among the logical operators, not binds tightest, then and, then or loosest.

08

Short-Circuit Evaluation

Python is lazy in a useful way: once and or or already knows the answer from the left side, it doesn't bother checking the right side at all.

and stops at the first False

If the left side of and is False, the whole expression must be False no matter what the right side is — so Python never looks at it.

or stops at the first True

If the left side of or is True, the whole expression must be True already — so the right side is skipped.

11

Chapter Recap

A quick-glance reference for revising later.

== !=

equal to, not equal to. Compares by value; a string and a number are never equal.

< > <= >=

ordering. Works on numbers and on strings (lexicographically). Mixed types raise TypeError.

and

True only when both sides are true. Short-circuits on the first False.

or

True when at least one side is true. Short-circuits on the first True.

not

Flips True to False and False to True.

Precedence

arithmetic, then comparisons, then not, then and, then or.
