What's a Variable, and Why Bother?

Definition: a variable is a named container used to store a value, so that value can be referenced, reused, or changed later in a program.

Once you create one, you can print it, reuse it in a calculation, or replace its value entirely — all just by using its name.

Think of a variable like a labelled jar. You put something inside — a number, a piece of text — and stick a name on the jar so you (and Python) know what's in it and where to find it.

The jar's label doesn't describe the jar itself — it points to whatever is currently inside.

The = Sign: Assignment, Not Equality

In maths, = means "these two things are equal." In Python, it means something different.

Definition: assignment means storing the value on the right under the name on the left. It's an instruction, not a claim.

Does = check whether two things are equal in Python?
age = 12

age = 12 doesn't ask "is age equal to 12?" — it commands "store 12 under the name age." Python checks equality with a different symbol, ==, which we'll meet properly once we cover conditions.

A variable's value isn't locked in forever — assigning a new value to the same name simply replaces what was there.

Declaration vs Initialization, Python-Style

Declaration: telling a program that a name is going to exist.

Initialization: giving that name its first value.

In some languages, these are two separate steps. In Python, they happen at the same moment: the instant you assign a value to a name, that name springs into existence, already holding that value.

So what happens if you use a name before assigning it anything? Python has no idea what you're talking about, and raises a NameError — Python's way of saying "I don't recognise this name," because in Python a name doesn't exist at all until an assignment creates it. 04

Naming Rules: What Python Will Allow

Python enforces a strict set of rules for what a variable name is allowed to look like. Break one, and Python won't create the variable at all — it'll refuse to run.

  • Must start with a letter or an underscore _
  • Can contain letters, numbers, and underscores after that first character
  • Cannot contain spaces
  • Cannot contain symbols like -, @, !
  • Cannot start with a number
  • Is case-sensitive — age, Age, and AGE are three different names
  • Cannot be one of Python's reserved keywords — words like if, for, while, class, def

Naming Conventions: Rules vs Recommendations

Rule: enforced by Python — break it, and your code won't run.
Convention: a widely agreed-on good habit — break it, and your code still runs fine, but it's harder for humans to read.

Enforced byPython itselfGood habit, agreed by programmers

The most common Python conventions: use lowercase words, separate them with underscores (called snake_case — writing multi-word names in lowercase with underscores between the words, like total_marks), and pick names descriptive enough that someone else could guess what they hold.

Whole Numbers: int

Definition: an int (short for integer) is any whole number — positive, negative, or zero — with no decimal point at all.

Does Python's int have a fixed maximum size, the way it does in some other languages?

Python integers can grow as large as your computer's memory allows. Other languages often set aside a fixed number of bits — the 0-or-1 switches you met back in Chapter 1 — for every whole number, which puts a hard ceiling on how big it can get (commonly 32 or 64 of those switches). Python doesn't do that: it simply uses as many bits as your number actually needs, so there's no fixed ceiling to hit. Try it below.

Decimal Numbers: float

Definition: a float is any number written with a decimal point — 1.55, -3.2, even 5.0. The decimal point is what makes it a float instead of an int, even if the value is a whole number.

Predict the output
print(0.1 + 0.2)
Output
0.30000000000000004

Not a bug — a float always uses a fixed set of 64 bits (the same 0-or-1 switches from Chapter 1) to store each decimal number. That's extremely precise, but with only a fixed number of switches to work with, some decimal fractions can't be stored perfectly exactly — much like how ⅓ can't be written exactly as a decimal either. That's what produces tiny leftovers like this.
